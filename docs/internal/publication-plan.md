# Подготовка публичного выпуска

**Статус: опубликовано.** Репозиторий: https://github.com/zykovkristian/3D-print-FDM-calculator
(`origin/main` = `6c8e6d4`, 51 файл). Публикация сделана fast-forward: история
`origin/main` не переписывалась, внутренние файлы остались только в локальной
ветке `main`.

## Решённый способ публикации

Публичную версию готовить в локальной ветке `public` с одним корневым коммитом.
В публичный репозиторий отправлять только эту ветку как `main`. Текущую `main`
с внутренней историей не отправлять: так внутренние документы не появляются ни
в дереве, ни в истории публичного репозитория. Каждый следующий снимок
публикуется fast-forward поверх предыдущего — переписывать уже опубликованную
историю не нужно.

Первый снимок пришлось отправлять force-push: до него `origin/main` был
корневым коммитом, не родственником нового. Дальше публикация идёт обычным
`git push origin public:main`.

## Исключить из публичного снимка

1. `AGENTS.md` и `context.md` — внутренние правила и состояние проекта.
2. `docs/session-log.md` — машинный журнал сессии.
3. `docs/MVS_dialoge.md` — рабочая переписка.
4. `docs/plans/plan-isolated-tests-logic.md` — внутренний план с локальным путём.
5. `docs/internal/monetization-and-protection.md`, `docs/internal/technology-packaging.md`, `docs/internal/publication-plan.md` — внутренняя стратегия и порядок выпуска.
6. `.kilo/` и любые локальные секреты/учётные данные.

## Перед реальным запуском

1. Убедиться, что все незакоммиченные изменения, включая пользовательские правки MVS, включены осознанно; ничего не сбрасывать и не перезаписывать.
2. Закрыть приоритетные технические пункты `context.md` §7: проверка G-code на принтере, ограничения экструзии, перенос и согласование протокола в интерфейсе, обновление анализа дефицита массы и блока потолков, проверка матрицы на печати.
3. Перепроверить применимость PolyForm Noncommercial к проекту и подготовить корпоративный договор. Уточнить контакт для лицензирования.
4. Подготовить изображения/короткое видео демонстрации. Внешние материалы и утверждения о производительности должны иметь источник.
5. Решить судьбу Google Fonts в `tools/filament_test_protocol.html`: сейчас есть внешний запрос, хотя при отсутствии сети остаётся системный шрифт.
6. Проверить актуальность текста README, ссылки, CI, лицензии и список исключённых файлов.

## Публичное дерево

Включить пользовательские инструменты, документы методики, тесты, README, лицензию, коммерческий контакт, правила вклада, кодекс поведения, SECURITY, CI и презентационные материалы. Исключения указаны выше; стратегические документы монетизации и упаковки оставить во внутренней ветке.

## Как опубликовать позже

1. Создать новый пустой репозиторий на GitHub под выбранным именем; не подключать его к внутренней `main`.
2. Проверить `git log public --oneline` (ровно один коммит) и `git ls-tree -r public --name-only` (нет исключённых путей).
3. После отдельного подтверждения отправить только `public` в новый репозиторий как его `main`.
4. Включить GitHub Pages для статического сайта и проверить локальную страницу и опубликованный URL.

Push, создание репозитория и включение GitHub Pages в этой задаче не выполняются.
