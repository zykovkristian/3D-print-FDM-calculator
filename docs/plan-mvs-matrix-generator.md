# Генератор матрицы MVS: `tools/mvs-matrix.html`

## 1. Цель и границы

**Цель.** Самостоятельная HTML-страница, которая генерирует G-code матрицы
«температура × объёмная скорость» для FDM-принтера: N цилиндрических ячеек,
в каждой ячейке свой VS, температура меняется зонами по высоте, все ячейки
внутри зоны сравнимы между собой.

**Не входит.** Слайсинг, подключение к принтеру, печать, калибровка FR/PA,
подбор пластика. Страница считает и пишет файл, ответственность за запуск
на принтере остаётся у пользователя.

**Заменяет.** `docs/MVS_Matrix_Labyrinth_GCode_Generator.html` (вёрсия 0.2).
Тот файл не удаляется этим планом: он источник идей, а не регрессия.

## 3. Ключевой расчёт: чем обоснована длина пути

В тестах Orca/Bambu/Ellis длину пути никто не задаёт в метрах. Ограничение
другое — **сколько пластика должно пройти через сопло, чтобы поток стал
установившимся**. В проекте этот критерий уже записан: промывка 50 мм прутка
= 120 мм³ ≈ 5 объёмов расплава (`docs/temperature-flow-matrix.md:78`),
объём расплава 25 мм³ (`:35`).

Что это даёт для матрицы:

1. Длина нужна не сама по себе, а как **объём выдавливания при компактной
   высоте**. Длинная спираль позволяет набрать объём за малое число слоёв,
   не строя высокую башню.
2. Второе ограничение — **время пребывания** `t = V/Q`. При Q = 5 мм³/с
   расплав стоит в сопле 5 с; слишком высокая зона на малом потоке даёт
   деградацию, а не измерение. Отсюда высота зоны ограничена сверху.
3. Третье — **одинаковый путь во всех ячейках**. Если путь разный, отличие
   в результате принадлежит геометрии, а не VS. Поэтому контур слоя — один
   шаблон, копируется со сдвигом, меняется только `F`.

Целевая длина 400–500 мм из диалога при двухветвевой схеме перевыполняется
в 1,5 раза уже на одном слое, то есть требования она не лимитирует.
Реальный дефицит — кинематика в центре спирали (§4).

## 4. Расчётные значения (эталон PLA, A1 mini)

Вход: `D = 36`, `lw = 0,48`, `lh = 0,20`, `gap = 0,72`, `a_max = 10 000`,
VS `5/8/11/14/17/20`, T `190…220` шаг 10, зона `10 мм`, 6 ячеек.

```
A_line  = lw · lh              = 0,096 мм²
A_fil   = π·(1,75/2)²          = 2,4053 мм²
R_out   = D/2 − lw/2           = 17,76 мм
g       = lw + gap             = 1,20 мм
v_max   = Q_max / A_line       = 208,33 мм/с      (Q = 20)
a_eff   = 0,8 · a_max          = 8 000 мм/с²
r_min   = v_max² / a_eff       = 5,42 мм
ΔR      = R_out − r_min        = 12,34 мм
n       = ΔR / (2·g)           = 5,14 витка на ветвь
L_ветвь ≈ 2π·((R_out+r_min)/2)·n = 374 мм
L_слой  = 2·L_ветвь + π·(g/2)  ≈ 750 мм          ← одинаково во всех ячейках
V_слой  = L_слой · A_line      ≈ 72 мм³          ≈ 2,9 объёма расплава
```

Проверка кинематики по радиусу (`a_треб = v²/r`, v = 208,33):

| r, мм | a_треб, мм/с² | при a_max 10 000 |
|---|---|---|
| 17,76 | 2 444 | проходит |
| 8,0 | 5 426 | проходит |
| 5,42 | 8 000 | граница (заложен запас 20 %) |
| 2,0 | 21 700 | **не проходит** |

Отсюда: спираль до точки невозможна на высоком VS. `r_min` — расчётная
величина, а не косметика. Разворот между ветвями идёт полукругом радиусом
`g/2 = 0,6 мм`, где прошивка держит только `√(8000·0,6) = 69 мм/с`
(`Q = 6,6 мм³/с`). Поэтому скорость на каждом участке урезается по
локальной кривизне и урезанные участки помечаются в отчёте.

**Итоги прогона по умолчанию:** 4 зоны × 50 слоёв = 200 слоёв, высота
40 мм; суммарный путь 900 м; 86,4 см³ ≈ 107 г PLA; время экструзии
≈ 2,4 ч (без ускорений, переходов и прогревов); строк ≈ 690 тыс. при
адаптивном шаге (см. §5.3).

## 5. Архитектура

### 5.1. Файл и экспорт

Один файл `tools/mvs-matrix.html`: HTML + CSS + `<script>`, без сборки,
без зависимостей, открывается двойным щелчком. Работает с `file://`.

Внутри `<script>` — маркер, по которому тест отрезает ядро:

```js
/* ============ ЯДРО ============ */
... чистые функции ...
if (typeof module !== 'undefined') module.exports = { ... };
/* ============ ИНТЕРФЕЙС ============ */
... DOM, отрисовка, обработчики ...
```

Тот же приём, что в `tests/model.test.mjs:8`, чтобы тесты гонялись в `node`
без браузера.

### 5.2. Чистое ядро (экспортируется)

| Функция | Вход | Выход |
|---|---|---|
| `PRESETS` | — | таблица принтеров: стол, высота, `v`, `a`, `Q_hot`, сопло |
| `FLAVORS` | — | таблица команд: homing, bed, wait, fan, accel, park, end |
| `defaults()` | — | параметры по умолчанию (пресет A1 mini, PLA) |
| `derive(p)` | параметры | все производные: `A_line`, `A_fil`, `g`, `v_max`, `r_min`, `n`, `L`, `V`, число слоёв, высота |
| `cellPath(p, i)` | параметры, индекс | массив точек `{x, y, seg}` одного слоя ячейки (шаблон, копия со сдвигом) |
| `layerFeed(p, pts, Q)` | | массив `F` по точкам с учётом кривизны |
| `validate(p)` | параметры | `[{level, field, code, msg}]` |
| `compose(p)` | параметры | `{gcode, report}` — текст и сводка |
| `audit(gcode, p)` | текст, параметры | `{E, layers, zTop, bbox, maxF, maxA, mismatches}` |

`cellPath` для всех `i` возвращает **геометрически тот же** массив (сдвиг
добавляется при записи команд), поэтому равенство длин — не совпадение, а
свойство конструкции.

### 5.3. Траектория слоя (двухветвевая)

Один слой ячейки, непрерывно, без разрыва:

1. **Ветвь A** — архимедова спираль от `R_out` к `r_min`:
   `r(θ) = R_out − (ΔR/(2πn))·θ`, `θ` от `0` до `2πn`, обход против часовой.
2. **Разворот** — полукруг радиусом `g/2` в точке `r_min`, переход на
   угловое смещение `π`.
3. **Ветвь B** — та же спираль обратно, `r_min → R_out`, со смещением `π`:
   дорожки B ложатся между дорожками A, зазор `gap` обеспечен.

Дискретизация адаптивная по стреле прогиба: `chord = √(8·r·0,02)`, зажатая
в `0,3…3 мм`. Это ≈ 1,3 мм в среднем, ≈ 690 тыс. строк на прогон по
умолчанию. Шаг дискретизации не влияет на длину в пределах 1 %.

Старт слоя — в одной точке (`θ = 0`, внешний радиус). Решение 9: шов
фиксирован, служит репером для осмотра. Шов попадает на видную сторону —
это принято сознательно и вынесено в отчёт.

Следующий слой: `G1 Z` на `+lh`, возврат в точку старта без экструзии
(по решению 1 — подъём Z, а не непрерывная спираль по Z).

### 5.4. Порядок печати

```
для каждой температурной зоны b:
    если b > 0: M104 → парковка → M109 → выдержка
    для каждого слоя k внутри зоны:
        для каждой ячейки c (слева направо, по росту VS):
            печать контура ячейки c на Z(k)
```

Все ячейки проходят слой `k` до перехода на `k+1` — это условие сравнимости
(ключевая идея диалога). Тест проверяет порядок по индексам команд.

### 5.5. Переходы

| Переход | Команды |
|---|---|
| ячейка → ячейка (тот же слой) | `G1 E−retract`, `Z+0,6`, `G0 X Y`, `Z−0,6`, `G1 E+retract`, `G92 E0` |
| слой → слой (внутри зоны) | `Z+0,4`, travel к старту, `Z` на новый слой |
| граница зоны | `E−retract`, `Z+2`, `G0` за габарит детали, `M104 S(T)`, `M109 S(T)`, `G4 S(dwell)`, возврат, `Z` на слой |
| brim | до первого слоя ячеек, один общий контур |

Парковка считается от bbox детали плюс запас; координата выбирается так,
чтобы не выйти за стол. Длительность выдержки — параметр (по умолчанию 5 с).

### 5.6. Метка границы зон (опция, по умолчанию выключена)

На первом слое каждой новой зоны внешний радиус ячейки печатается как
`R_out + 0,6 мм` на **один** слой — видимая полка по всему периметру.
Геометрия ячейки на остальных слоях не меняется, оценка полки исключена
из сравнения и помечена в G-code комментарием `; boundary bead`.

Ограничения, которые проверяет `validate`: полка не выходит за габарит
стола; при `gap < 1,0` полка не включается (соседние ячейки сблизятся).

### 5.7. Brim

Общий контур вокруг группы ячеек, `offset = 0,3 мм` от внешних стенок.
Параметры: включён/выключен, витков `1…8` (по умолчанию 3), слоёв `1…3`
(по умолчанию 1), зазор `0…2 мм`. Печатается на слоях `1…N`, Z совпадает
со слоями ячеек. При выключении в G-code не появляется ни одной команды
brim — тест это проверяет.

### 5.8. Команды по flavor

| Что | Bambu | Marlin | Klipper |
|---|---|---|---|
| хоуминг | `G28` | `G28` | `G28` |
| стол | `M140 S` / `M190 S` | так же | так же |
| сопло | `M104 S` / `M109 S` | так же | так же |
| обдув | `M106 P1 S` | `M106 S` | `M106 S` |
| ускорение | `M204 S` (может игнорироваться) | `M204 S` | `M204 S` |
| ожидание | `M400` | `M400` | `M400` |
| конец | `M104 S0`, `M140 S0`, `M106 S0`, `G28 X Y` | так же | так же |

Свои макросы Bambu (AMS `M620`, `G29`, продувка) генератор **не выдумывает**.
Для пресетов Bambu пролог минимальный и безопасный (`G90`, `M83`, `G28`,
`M190`, `M104`, `M109`, `G92 E0`), а в интерфейсе есть поле «дополнить
пролог» и отдельное поле «дополнить эпилог» — вставленный текст идёт как
есть и помечается в отчёте как непроверенный.

### 5.9. Обратная проверка (`audit`)

После сборки текст разбирается регулярками и сверяется с расчётом:

- сумма `E` по всем командам против `V / A_fil`;
- множество значений `Z` даёт число слоёв и высоту;
- bbox по `X`/`Y` внутри стола;
- максимальный `F` не выше `v_max` пресета;
- максимальное `F²/r` по траектории не выше `a_max`;
- наличие `G28`, `M190`, `M109` до первой экструзии;
- при включённом brim — есть команды brim, при выключенном — нет.

Расхождение больше допуска (0,5 % по `E`, 1 слой по `Z`) — блок «ошибка
самопроверки» с указанием, какое поле расчёта не совпало.

## 6. Интерфейс

Одна страница, две колонки на широком экране: слева параметры, справа
предпросмотр, отчёт и код. На узком — одна колонка, параметры сворачиваются
в аккордеон. Тёмная тема, палитра ближе к текущему проекту.

### 6.1. Порядок блоков

| # | Блок | Содержимое |
|---|---|---|
| 1 | Шапка | название, переключатель RU/EN, «Сбросить», индикатор «изменено с последней генерации» |
| 2 | Принтер | пресет (A1 mini, A1, P1P, P1S, X1C, своя), flavor, стол X/Y, макс. высота, `v_max`, `a_max`, `Q_hot`, сопло |
| 3 | Материал | диаметр прутка, плотность, Flow Ratio, цена за кг, температура стола, обдув |
| 4 | План факторов | список VS через запятую, список температур (начало/конец/шаг или перечисление), высота зоны, ячеек по X и Y, шаг между центрами |
| 5 | Ячейка | диаметр, ширина линии, высота слоя, зазор дорожек, `r_min` (авто/ручно), витков (авто/ручно), угол старта |
| 6 | Переходы и адгезия | brim (вкл, витков, слоёв, зазор), метка границы зон (вкл, размер), выдержка на смене T, точка парковки (авто/ручно), ретракт |
| 7 | Дополнения | «дополнить пролог», «дополнить эпилог», имя файла |
| 8 | Проверки | список найденных проблем с уровнем и полем, клик ведёт к полю |
| 9 | Предпросмотр | вкладки «Стол», «Слой», «3D» |
| 10 | Отчёт | таблица по ячейкам и итоги |
| 11 | G-code | кнопки «Сформировать», «Копировать», «Скачать», аудит, окно кода с подсветкой комментариев |

Порядок 2→7 отражает порядок решений пользователя: сначала машина, потом
план, потом геометрия, потом мелочи. Всё, что можно вывести, выводится
и показывается серым рядом с полем — не заставляем вводить руками.

### 6.2. Проверки и уровни

| Уровень | Что значит | Поведение |
|---|---|---|
| `error` | генерировать нельзя | кнопка «Сформировать» неактивна, поле подсвечено |
| `warn` | генерировать можно, но результат исказится | кнопка активна, предупреждение в отчёте и в шапке G-code |
| `info` | свойство модели, не дефект | только в отчёте |

Правила `validate`:

| Код | Уровень | Условие |
|---|---|---|
| `bed-x`, `bed-y` | error | bbox с brim выходит за стол |
| `bed-h` | error | высота больше рабочей |
| `pitch` | error | `pitch < D + 2·gap` при ячейках >1 по оси |
| `gap` | error | `gap < 0,1 мм` — дорожки слипнутся |
| `self` | error | min-расстояние между несоседними точками < `lw` |
| `rmin` | error | `r_min ≤ g/2` — разворот не помещается |
| `turns` | error | `n < 1` — спирали нет |
| `v-tool` | error | `v_max` выше `v_max` пресета |
| `q-hot` | warn | максимальный VS выше `Q_hot` (проверяем то, чего нет) |
| `f-cap` | info | доля пути, урезанного по кривизне, > 2 % |
| `t-cap` | warn | верхняя T выше `T_cap − 15` |
| `band` | warn | число слоёв в зоне не целое (`band % lh ≠ 0`) |
| `res-time` | warn | время пребывания при минимальном VS > 8 с |
| `cell-time` | info | разброс времени слоя между ячейками, % |
| `accel-set` | warn | `a_max` пресета меньше требуемого для `v_max` при `R_out` |
| `prologue` | error | в собранном коде нет `G28` или `M190` до первой экструзии |
| `extra` | info | вставлены пользовательские пролог/эпилог — не проверялись |
| `bead` | warn | метка границы включена, но `gap < 1,0` |

### 6.3. Предпросмотр

**«Стол»** — SVG сверху, вид на весь стол: bbox, brim, ячейки кругами с
подписью VS, температурная шкала по Y отсутствует (температура по высоте,
не по столу). Клик по ячейке — подсветка строки отчёта.

**«Слой»** — SVG одной ячейки или всех ячеек вместе: реальная полилиния
сгенерированного слоя, ползунок номера слоя, отметки шва, отметки
урезанных по кривизне участков красным. Это главный контроль формы: если
дорожки слиплись или спираль врёт, здесь видно до печати.

**«3D»** — самописная ортографическая проекция на `<canvas>`, вращение
мышью, отрисовка подвыборки точек (≈20 тыс.): цилиндры, полосы зон, две
теплокарты переключателем (VS по ячейкам, T по высоте). Без WebGL и без
библиотек.

### 6.4. Отчёт

Таблица по ячейкам: `VS`, линейная `v`, `F`, путь на слой, время на слой,
время всего, пластик, доля пути урезанного по кривизне. Итоги: высота,
слоёв, суммарная длина, масса, время экструзии, приблизительная стоимость,
размер файла в строках и КБ, число зон, предупреждения.

Отдельным блоком — **что искажалось и почему**: переход при смене VS не
компенсируется (решение 12), первые ≈ 1 слой каждой ячейки показывает
переходный процесс; время слоя между ячейками различается, ось VS
частично смешана с охлаждением; шов фиксирован на видной стороне.

### 6.5. Локализация и память

Словарь `I18N = { ru: {...}, en: {...} }`, переключатель в шапке, выбор
сохраняется. Все подписи, подсказки, уровни проверок и отчёт — из словаря;
в G-code только латиница и комментарии на английском.

`localStorage['mvs.matrix.v1']` — все параметры и язык. Свой ключ, не
пересекается с `plc.v1` калькулятора. Восстановление при загрузке; «Сбросить»
возвращает пресет по умолчанию и чистит ключ.

## 9. Риски и как они закрыты

| Риск | Почему реален | Что делаем |
|---|---|---|
| Прошивка не держит `a` на малом радиусе | фото 2 показывает спираль в точку, физически недостижимую на VS 20 | `r_min` из кинематики, ограничение `F` по кривизне, урезанные участки в отчёте |
| Дорожки слипаются в центре | шаг по радиусу постоянный, а кривизна растёт | `gap` проверяется по фактическим точкам, а не по формуле |
| Ячейка отрывается от стола | цилиндр в одну линию без дна | brim включён по умолчанию, общий контур |
| Разный VS — разное время слоя | арифметика, не дефект | показываем как `info`; решение 5: не выравниваем |
| Первые слои ячейки невалидны | расплав прошлой ячейки в сопле | решение 12: без компенсации; предупреждение в отчёте, ≈1 слой |
| Файл слишком велик для принтера | 690 тыс. строк | adaptive chord, размер показан до скачивания; поле «шаг дискретизации» |
| Пользователь ставит свои лимиты наугад | публичный инструмент | пресеты подставляют реальные значения, «своя машина» требует все поля |
| Bambu игнорирует часть команд | `M204` может не применяться | flavor-таблица, предупреждение `accel-set`, рекомендация проверить в симуляторе |

## 10. Что остаётся открытым

1. **Реальная проверка на принтере.** Ни один расчёт кинематики не заменяет
   печать: нужно напечатать одну ячейку при VS 20 и убедиться, что центр
   спирали не недолит. Это пункт для профиля проекта, а не для этого плана.
2. **Обдув.** При разном времени слоя обдув влияет по-разному; выравнивание
   отклонено сознательно, но значение обдува по умолчанию (30 %) взято
   из диалога и не проверено для такой геометрии.
3. **Адгезия.** Brim общего контура — гипотеза: на высоком тонком цилиндре
   без дна может понадобиться brim на 3 слоя. Значение по умолчанию — 1.
4. **Версия 0.2** остаётся в `docs/` как история; удалять или нет — решает
   пользователь отдельно, этот план файл не трогает.
