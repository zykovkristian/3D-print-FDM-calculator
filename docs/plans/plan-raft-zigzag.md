# План исправления: непрерывная зигзагообразная заливка плота (raft)

Дата: 2026-11-28. Автор: researcher (анализ, без правки кода — запись кода закрыта для слоя).

## 1. Симптом

При печати плота каждая линия заливки печатается от одного края к другому
(`G1`), а затем экструдер возвращается холостым перемещением (`G0`) к началу
следующей линии. Это даёт длинные холостые ходы «от края до края» и ухудшает
качество/скорость печати плота.

## 2. Корневая причина (по коду `index.html`)

Функция `raftFillLines(d, gap, angle, step)` (строки ~1169–1202) возвращает
массив **отдельных отрезков** `[[x1,y1,x2,y2], ...]`. В генераторе G-code
(блок `effectiveRaftOn`, строки ~1494–1502) каждый отрезок печатается как
отдельная пара:

```
G0 X<x1> Y<y1> Z<z> F3600       // холостой подвод к началу линии
G1 X<x2> Y<y2> E<e> F<layerF>   // экструзия
```

Полосы (strips) идут монотонно снизу вверх, и направление каждого отрезка не
чередуется: конец одной полосы (правый край) и начало следующей (левый край)
лежат на противоположных сторонах — отсюда длинный холостой возврат. Комментарий
функции обещает «монотонный проход без лишних перемещений», но реализация его
не даёт: порядок отрезков на полосе может реверсироваться (`spans.slice().reverse()`),
однако направление каждого отрезка остаётся `s[0]→s[1]`, поэтому зигзага нет.

## 3. Целевое поведение

Заливка каждого слоя плота — **одна непрерывная зигзагообразная линия**
(serpentine):

- чётные полосы печатаются слева→направо,
- нечётные — справа→налево,
- переходы между полосами и между отрезками одной полосы — короткие диагонали
  на краю, печатаются с экструзией (`G1` с `E>0`), без `G0` «от края до края».

Периметр слоя (замкнутый контур) остаётся отдельной операцией — он уже
непрерывен.

## 4. Предлагаемое изменение

### 4.1. Заменить `raftFillLines` на `raftFillPath`

Функция должна возвращать **полилинию** `[[x,y], ...]` в мировых координатах
вместо массива отрезков. Логика поворота координат сохраняется; меняется только
порядок/направление полос и сборка точек.

```js
// Путь заливки слоя — непрерывная зигзагообразная полилиния.
function raftFillPath(d, gap, angle, step) {
  const cs = raftCircles(d, gap);
  if (!cs.length) return [];
  let cx = 0, cy = 0;
  for (const c of cs) { cx += c.x; cy += c.y; }
  cx /= cs.length; cy /= cs.length;
  const co = Math.cos(angle), si = Math.sin(angle);
  const toRot = (x, y) => {
    const dx = x - cx, dy = y - cy;
    return [cx + dx * co + dy * si, cy - dx * si + dy * co];
  };
  const toWorld = (x, y) => {
    const dx = x - cx, dy = y - cy;
    return [cx + dx * co - dy * si, cy + dx * si + dy * co];
  };
  const rcs = cs.map(c => { const [rx, ry] = toRot(c.x, c.y); return { x: rx, y: ry, r: c.r }; });
  let minY = Infinity, maxY = -Infinity;
  for (const c of rcs) { minY = Math.min(minY, c.y - c.r); maxY = Math.max(maxY, c.y + c.r); }
  const pts = [];
  const n = Math.max(1, Math.ceil((maxY - minY) / step));
  let stripIndex = 0;
  for (let i = 0; i <= n; i++) {
    const y = Math.min(minY + i * step, maxY);
    let spans = spansAt(rcs, y);
    if (!spans.length) continue;
    // Зигзаг: чётные полосы — слева направо, нечётные — справа налево.
    const reverseStrip = (stripIndex % 2 !== 0);
    if (reverseStrip) {
      spans = spans.slice().reverse().map(s => [s[1], s[0]]);
    }
    stripIndex++;
    for (const s of spans) {
      const a = toWorld(s[0], y), b = toWorld(s[1], y);
      pts.push(a);
      pts.push(b);
    }
  }
  return pts;
}
```

Ключевое отличие от старой версии:
1. `reverseStrip` реверсирует **и** порядок отрезков, **и** направление каждого
   отрезка (`[s[1], s[0]]`), а не только порядок.
2. Результат — полилиния точек, а не набор независимых отрезков.

### 4.2. Обновить генерацию G-code в блоке `effectiveRaftOn`

Заменить блок (строки ~1494–1502):

```js

      // возвратов «от края до края»): один G0 к началу, затем цепочка G1.
      const path = raftFillPath(d, gapLayer, angle, step);

        out += `G0 X${path[0][0].toFixed(3)} Y${path[0][1].toFixed(3)} Z${zRaft.toFixed(3)} F3600\n`;

          const dist = Math.hypot(path[i][0] - path[i - 1][0], path[i][1] - path[i - 1][1]);

          const e = dist * d.A_line / d.A_fil;

      }
```

### 4.3. Совместимость с тестами

Тесты (`tests/mvs-matrix.test.mjs`) парсят `G1`-сегменты и отслеживают `x,y`
по всем строкам `G0/G1`; переходы (короткие диагонали) будут учитываться как
`G1`, но фильтрация `> 5 мм` в тесте «raft: заливка соседних слоёв идёт
перекрестно» отсекает их от расчёта угла заливки. Угол линий заливки задаётся
`angle` (±45°) и не зависит от направления обхода, поэтому тест углов остаётся
зелёным. Границы raft по X/Y (`minX/maxX`) сохраняются, так как набор точек
заливки тот же.

Единственное изменение в выводе: исчезают `G0`-подводы между линиями заливки
одного слоя (остаётся один `G0` к началу полилинии). Это и есть цель.

## 5. Что не меняется

- Периметр слоя (замкнутый контур) — без изменений.
- Углы заливки соседних слоёв (±45°) — без изменений.
- Параметры скорости/температуры/плотности — без изменений.
- Функции `raftOutline`, `spansAt`, `raftCircles`, `raftBBox` — без изменений.
